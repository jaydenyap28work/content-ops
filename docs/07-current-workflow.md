## 2. Existing Content Categories / Rhythm

### 文件明确支持的内容分类

1. **引流内容**：周一发布，偏轻松、娱乐或趣味，目标是获取曝光与流量。
2. **老板 IP 内容**：周三发布，用于强化老板个人认知与品牌人设。初期以个人认知、行业观点为主，后续逐步延伸到创业经历、公司优势、顾客探访、内部管理、老板日常和团队风貌。
3. **转化／销售内容**：周五发布，承接前端流量并推动销售转化。
4. **实体体验与品牌差异化内容**：包括新装修 showroom、到店体验、公司实体场地、workshop、售后复盘培训等。
5. **行业与经营观点内容**：包括行业揭秘、企业经营、客户选择、年轻员工／企业文化等；Planner 中现有选题主要属于老板观点型内容。
6. **活动与团队场景内容**：会议要求后续活动全程录制再剪为短内容，并计划在 11 月结合团建场景产出内容。
7. **老板个人形象延伸内容**：会议提到运动等个人主题，以及尝试对谈类内容。

### 当前发布节奏与提前制作要求

- 基础发布框架为：周一引流、周三老板 IP、周五转化／销售，即每周三个发布触点。
- 会议总结明确要求常规情况下提前 1 周完成下一周全部内容的拍摄与剪辑。
- 会议章节摘要另提到“常规按周提前完成后续两周的拍剪”，与“提前 1 周”存在口径差异，需确认正式规则。
- 行业热点或突发营销事件可调整排期，目标是最快 2 天完成相关内容并发布。
- 会议同时出现“9 月每周 3 条视频”及“新增老板 IP 后每周新增约 3 条内容”的表述；两者是否指同一范围尚不明确。

## 3. Existing Production Workflow

当前资料可以支持的流程如下；未明确部分保留为问题，不补写为既定流程。

### Idea / Topic

- 选题来自团队共创、行业热点、老板观点、公司／客户场景和历史内容方向。
- Planner 的任务标题承担选题记录功能。
- 会议决定建立共享群同步创意、素材与进度。

### → Script

- 公司已有历史脚本库与过往内容样本。
- 9–10 月老板 IP 脚本已初步制定。
- 内容由团队共创后确认，但谁撰写、谁批准、如何管理版本未明确。

### → Shooting

- 当前由 intern 与营销负责人共同拍摄。
- 阿辉将参与拍摄、剪辑和内容策划全流程；9 月将以公司老板 IP 为测试项目试拍不同角度、运镜与风格。
- 当前提到使用 iPhone；采购 DJI Pocket 类设备属于已作出的后续安排。

### → Editing

- 当前只有 1 名专职剪辑人员，常规支撑约每周 2 条内容。
- 长素材、多画面的内容可能需要超过 3 天剪辑。
- 阿辉将协助分担；AI 工具用于口播气口裁剪和基础粗剪仍属于规划。

### → Review / Scheduling

- 资料支持“团队共创后确认内容”、提前排期以及热点可调整顺序。
- Planner 可记录任务状态并展示月历，但没有独立的 Review 状态、审核人、修改轮次或 scheduled 时间。
- 最终由谁审核脚本、成片及排期，资料未明确。

### → Publishing

- 公司官方账号由营销团队发布并回复评论。
- 老板个人账号计划由老板本人发布和互动。
- 部分已剪内容曾因政策变动、平台功能调整而暂未发布，说明“剪辑完成”与“实际发布”并非同一状态。

## 7. Planner Limitations

> **Product Analysis：以下是基于现有资料的产品分析，不代表团队已经发生的全部问题，也不代表正式 Product Spec。**

### 对单老板、短期排期可以解决什么

- 提供单月月历视图，直观看到某天的选题。
- 用详情表记录日期、任务标题、描述、状态、优先级和备注。
- 用“未开始／进行中／已完成”提供轻量进度标识。
- 在月历与详情之间提供跳转思路，并预留上传 Google Sheets 的使用方式。
- 对少量、固定节奏的老板 IP 任务，可作为简单排期和选题清单。

### 未来扩展时的结构性限制

- **多 Content**：当前没有内容类型、账号、平台、格式、campaign、脚本版本或内容之间的关联字段；月历每天默认 3 个任务位，扩展依赖手工插行。
- **多员工**：没有 Owner、协作者、交接人、审核人、更新时间或角色权限，难以确认谁应在何时执行或更新。
- **多 Client**：没有 Client / Brand、行业、项目、服务范围或客户隔离字段，无法支持会议中计划的外部客户与“一行业一客户”规则。
- **Editing workflow**：单一 Status 无法表达待剪、粗剪、精剪、字幕、内部审核、客户审核、修改、scheduled、published 等不同阶段；也没有版本和 feedback 记录。
- **Analytics**：没有账号、平台、发布日期、播放、互动、线索或转化字段，无法把“露脸视频表现较高”等反馈系统化回流到选题。
- **Contribution**：没有选题、脚本、拍摄、剪辑、审核、发布各环节的参与人记录，无法为利润共享或团队贡献提供可审计依据。
- **Efficiency tracking**：没有计划／实际开始与完成时间、剪辑耗时、返工次数、逾期原因或产能指标，无法验证每周产能与流程提效。
- **Assets**：没有 Google Drive 素材链接、成片链接、封面、脚本附件或发布链接，表格无法成为资产索引。
- **一致性与维护**：月历和详情为手工双写，当前已出现日期／展示不同步；随着任务量增加，人工维护风险会扩大。
- **审计与历史**：没有状态变更记录、更新人和决策记录，无法还原任务为何延期、改题或未发布。

## 8. Requirements Already Implied by Existing Workflow

以下只总结现有资料已经暗示、且最值得未来 ContentOS 承接的能力；不构成完整系统设计。

1. **单一内容记录与多视图同步**：选题详情、月历和状态应来自同一记录，避免人工双写。
2. **明确内容分类与发布节奏**：能够区分引流、老板 IP、转化／销售及活动等内容，并对应账号、渠道和目标发布日期。
3. **生产阶段与交接可见**：至少能区分 Idea / Topic、Script、Shooting、Editing、Review / Scheduling、Publishing，并记录当前负责人。
4. **脚本与素材索引**：承接现有脚本库、历史样本和 Google Drive 素材链接，同时保留版本与确认状态。
5. **拍摄与剪辑标准承载**：让已确定的角度、运镜、字幕、转场和风格标准可以被团队与轮换 intern 重复使用。
6. **产能与截止时间可见**：支持提前制作要求、热点插单、剪辑耗时与每周负荷，帮助识别产能缺口。
7. **审核、排期与发布分离**：避免把“剪完”当作“已发布”，明确审核、scheduled、published 及未发布原因。
8. **团队贡献留痕**：记录谁提出选题、写脚本、拍摄、剪辑、审核和发布，为后续贡献与利润共享讨论提供事实基础。
9. **Client / Brand 维度预留**：现有业务明确计划从公司试点延伸到外部客户，因此未来需要在内容与资产上区分 Client / Brand。
10. **基础效果反馈**：把平台表现与内容类型、出镜方式和选题关联，支持后续用实际结果优化内容方向；现阶段不扩展为完整 Analytics 设计。
